## M1 宠物本体补齐

**目标**：把上游桌宠的"行为"补齐到与现状一致（不含 LLM）。

- [x] **完整动画链**：待机/转向/移动/随机动作分类，按权重选下一个，播完立即衔接（上游 `pickers` / 配置的 `animations` / `animationWeights`）
- [x] **素材导入**：上游 106 个透明动画全部导入并按分类识别（`scripts/import-animations.ps1`）
- [x] **左右转向与镜像**：`noMirror` 文字类动作的朝向规则
- [x] **屏幕漫游**：朝 facing 方向行走 + 空间检查（上游 `motion.planMove`，需把 `pickers.ts` / `motion.ts` 一并拷进 `reference/shared`）
- [ ] **多宠物**：配置多写几项即可多开（窗口层已按"每宠一窗"设计，主要是补跨窗状态）
- [ ] **跨窗碰撞**：`petCollision` 开关生效（动量守恒 + 恢复系数 0.995；上游 `physics.collidePet` 可复用，Rust 侧需要一个状态 broker 广播各窗位置/速度）
- [x] **右键级联菜单**：动作分类点播（上游 `shared/menu.ts` 是"树 + 渲染"两份可复用代码）
- [x] **气泡独立小窗**：不可聚焦 + 整窗点击穿透的纯显示窗，跟随宠物头顶定位（`src-tauri/src/bubble.rs`）
- [ ] **点击积分**：飞行中被按下 → 粒子 + 积分卡片（上游 `score.ts` / `score-popup.ts`）
- [x] **角落定位语义统一**："回到初始位置"与启动定位共用 `anchorPixel`
- [ ] **高 DPI 回归**：125% / 150% 缩放下的尺寸与命中精度
- [ ] **多显示器回归**：跨屏抛掷、显示器插拔/改分辨率（`display.rs` 已有指纹轮询）
- [x] **稳定性：持锁期间绝不跨线程动窗口**（一次真实死锁的修复 + 运行时看门狗；复盘见 `VERIFICATION.md` 6.7）
- [x] **稳定性：输入状态机两处真 bug**（"只有首次能甩出"的飞行标志漏复位、穿透态按下被死代码吞掉）
      + 新增 `?autotest=10` 重复甩出回归自测（复盘见 `VERIFICATION.md` 6.8）

**出口标准**：在与 `dsh-pet` 桌面模式相同的配置下，行为一致（动作链、漫游、抛掷手感、菜单项）。

## M2.5 外观与结构升级

起因：用户看过 M2 成品后提出"托盘菜单样式不好看、应用没有图标、设置界面杂乱且没有导航栏、
单只宠物的行为应当属于它自己"。

- [x] **应用与托盘图标**：`icon_art.rs` 用 SDF 画出小鲸鱼图标，
      `cargo run --example make-icon` 产出 `icons/` 全套（`.ico` 七个尺寸 + png + 托盘版）；
      托盘图标与 exe 图标**同一份绘制代码**
- [x] **自绘托盘菜单**：`tray_menu.rs` + `tray-menu.html`/`tray-menu-page.ts`
      （浅/深色跟随系统、圆角卡片、内联图标、粉色高亮；外点关闭；按内容变高）
- [x] **托盘菜单精简**：显示/隐藏合并为一个切换项；**开机自启移入设置窗口**；
      动作点播展开成按分类分组的可滚动列表（多宠时顶部有宠物切换）
- [x] **设置界面重做**：左侧竖向导航（宠物逐个列 + 通用分组）、跟随系统的浅/深主题、
      底部状态栏与保存；修掉"勾选项被挤成竖排文字""同行输入框高低不齐"两个布局 bug
- [x] **每只宠物独立行为**：`pets[].animations` / `pets[].animationWeights` 可选**整体覆盖**，
      不写则跟随全局；宠物页、右键菜单、托盘动作点播都用"这只宠物实际生效的池"
- [ ] 深色主题的真机观感回归（本机桌面为浅色，只验证了浅色）
- [ ] 托盘图标在通知区的可见性（Win11 默认收进"隐藏的图标"，需要用户手动设显示）

## M3 加分能力（需要自带 LLM）

> 设计说明见 [`LLM.md`](LLM.md)（与上游的对应关系、配置段、密钥存储、请求形状、记忆结构、
> 交互形态、验证策略）。上游那套 prompt 语义与失败处理已逐字侦察并记录，实现时照抄。

- [x] **LLM 适配层**：OpenAI 兼容 / DeepSeek / Ollama / 自定义；Key 用 **DPAPI** 加密存
      （`llm-key.bin`，不引 keyring）；HTTP 用 `ureq + native-tls`；在 **Rust 侧**发请求（CSP 不放行外部域名）
      —— 已落地并对着本地 mock 端到端验证（`VERIFICATION.md` 13.2~13.4）
- [x] **碎碎念**：按周期（默认 300s）生成一句 → 气泡显示 10s（复用上游 prompt 语义与人设默认值）
      —— 定时器在 Rust 侧（`whisper.rs`），页面只负责"说"（`runtime.ts::onWhisper`）+ 可选 whisper 动画
- [x] **默认零联网 + 设置页开关/自检**：原始配置启动零请求；「AI」页可配 provider/模型/Key 并一键自检
- [x] **对话**：宠物角上的单行输入窗 + `memory.json` 全量记忆（最近 N 轮进上下文）+ 回复走气泡
      —— 输入窗是本项目唯一的**可聚焦**辅助窗（要打字），托盘与右键菜单各有一个入口
- [x] **表情包配图**：碎碎念随机抽（描述注入提示词）/ 对话按语境选（末尾 `[图:名称]` 标记，只在池内命中才采纳）、
      气泡支持配图；素材由 `import-animations.ps1 -All` 导入，配置表随内置模板回落
      —— 见 `VERIFICATION.md` 第 15 节（含两个静默 bug 的复盘）
- [x] **余额 / 用量**：DeepSeek `/user/balance` + OpenCode `/zen/go/v1/usage`（provider 表、20s 超时、
  退避重试、结构化失败、托盘与右键入口、气泡 + 六档余额动画，档位算法与上游一致）
      —— 见 `VERIFICATION.md` 第 16 节（含真实 DeepSeek 余额验证）
- [ ] **多把 key 共存**：密钥库目前单槽位，"LLM 用 DeepSeek + 余额查 OpenCode"需要两把 key（下一轮改映射）
- [x] **真实 provider 联调**：DeepSeek `deepseek-chat` 下自检与对话各一次真跑通过；
      并因此修掉一个 mock 验不出的致命坑（https 传输层 panic，见 `VERIFICATION.md` 13.11）

**出口标准**：默认关闭所有联网功能（保持"零成本桌宠"），开启后可用。
